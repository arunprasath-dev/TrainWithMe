# Demo media & exercise catalogue

Everything the app ships is local: the exercise catalogue, one looping demo clip per movement
pattern and one list thumbnail per exercise. There is no network fetch, no CDN and no CDN fallback
— `docs/PLAN.md` §11 explains why v1 has no `INTERNET` permission at all.

## What is in the APK

| Path | Count | Purpose |
|---|---|---|
| `core/data/src/main/assets/exercises.json` | 62 exercises | Single source of truth for the catalogue |
| `core/data/src/main/assets/videos/<pattern>.mp4` | 13 | Looping demo clip per movement pattern |
| `core/data/src/main/assets/thumbnails/<exercise-id>.jpg` | 62 | 360 × 360 list thumbnail |

Both directories total well under 1.5 MB, so they are committed to Git rather than downloaded.

## Clip specifications

| Property | Value | Why |
|---|---|---|
| Resolution / aspect | 720 × 720, square | Fits the player slot at any width without letterboxing |
| Duration | 6 s, seamless loop | One repetition cycle; the player uses `REPEAT_MODE_ONE` |
| Frame rate | 24 fps | Small files, smooth enough for schematic motion |
| Codec | H.264 (`main`, level 3.1), `yuv420p`, `+faststart` | Plays on every API 26+ device, streams from assets without seek stalls |
| Audio | none (`-an`) | The player is muted by design; clips are muted on the device anyway |
| Palette | Ember `#FF6A3D` on ink `#0E1116` | Matches `core/designsystem/theme/Theme.kt` |

## How the clip for an exercise is resolved

```
Exercise.videoAsset  (per-exercise override, optional)
        │ absent
        ▼
MovementPattern.clipId  →  "videos/<clipId>.mp4"
        │ asset missing
        ▼
LoopingAssetVideo placeholder (VideocamOff icon) + technique cues
```

`PlannedExercise.videoAssetPath` performs the mapping, so the player and the plan generator can never
disagree about which file belongs to a movement.

## Adding real footage later (data-only change)

1. Drop the file in `core/data/src/main/assets/videos/`, named after the exercise id, e.g.
   `barbell-bench-press.mp4` (same specs as above, 6 s loop, no audio).
2. In `exercises.json`, set `"videoAsset": "barbell-bench-press.mp4"` for that exercise.
3. Run `./gradlew :core:data:testDebugUnitTest`. `ExerciseCatalogueTest` fails if a referenced clip
   is missing or suspiciously small, so a typo cannot ship.

No Kotlin change is required: the player already receives the resolved path.

## Regenerating the placeholders

```bash
python3 tools/generate_demo_videos.py            # all clips + thumbnails
python3 tools/generate_demo_videos.py --only squat --no-thumbs
```

The script needs Pillow and an `ffmpeg` binary (`FFMPEG=/path/to/ffmpeg` overrides discovery,
`pip install imageio-ffmpeg` provides one). Output is deterministic, so re-running it with no
arguments should produce a clean `git diff`.

## Licensing

All clips and thumbnails are generated by the script above — no third-party footage or stock media
is bundled, so the repository contains no media licence obligations. Replacing them with licensed
footage is a content decision that must be made before shipping.
