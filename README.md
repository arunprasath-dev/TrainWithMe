# TrainWithMe

A native Android app that turns a short body-composition and goal questionnaire into a
**personalised 8-week gym programme**, then coaches every session step by step — exercise by
exercise, set by set — with a demo video, technique cues, a rest timer and automatic
progressive overload.

Built with Kotlin + Jetpack Compose, offline-first: no account, no backend, and deliberately
**no `INTERNET` permission**.

> **Status:** The v1.0 baseline previously passed CI (debug/release builds, JVM tests and lint).
> This UX polish iteration adds a widget, Compose smoke tests and motion/accessibility changes; those
> changes still need a Java-enabled Gradle/CI run and device QA. `docs/UX-PLAN.md` tracks completed
> implementation work and the remaining external/device release gates.

---

## Open it in Android Studio

1. **Android Studio Ladybug (2024.2) or newer**, with **JDK 17**.
   `Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK = 17`.
2. `File → Open…` and pick the **repository root** (the folder containing `settings.gradle.kts`).
   Do not open a sub-module.
3. Let Gradle sync (the wrapper pins Gradle 8.9 and verifies its SHA-256). Accept the SDK 35
   prompt if asked.
4. Select the `app` run configuration and run on any **API 26+** device or emulator.

There is nothing else to configure: no API keys, no `local.properties` beyond the SDK path, no
network access required at runtime.

### Command line

```bash
./gradlew :app:assembleDebug        # build the debug APK
./gradlew testDebugUnitTest         # JVM unit tests (engine + data)
./gradlew :app:connectedDebugAndroidTest :feature:plan:connectedDebugAndroidTest :core:designsystem:connectedDebugAndroidTest  # Compose smoke tests
./gradlew :app:lintDebug            # Android lint (baseline: app/lint-baseline.xml)
./gradlew :app:assembleRelease      # R8 + resource shrinking, unsigned
```

## What the user can do

| Flow | Screen | Highlights |
|---|---|---|
| Onboarding | `feature/onboarding` | Sex, age, height, weight, body-fat %, circumference, goal, experience, days/week, session length, equipment, disclaimer |
| Today | `feature/plan` dashboard | Next-session hero, week strip, animated adherence/reflection, compassionate return-after-break note, nutrition targets, quick weigh-in |
| Plan | `feature/plan` browser + day detail | 8-week mesocycle with deloads, per-day exercise list, "why this plan" explainability |
| Train | `feature/workout` | Session overview → **player** (video, cues, set logging, RPE, resilient rest timer, swap/skip) → recap, dismissible milestones, private-by-default share action |
| Progress | `feature/progress` | Weight and body-fat trend charts with spoken summaries, weekly volume bars, PRs, measurement log, session history |
| Quick access | Android home-screen widget | Offline next-session summary; opens the app without exposing body metrics |
| Settings | `feature/plan` settings | Units, theme, opt-in reminder time, rest-timer beep/haptic control, keep-screen-on, export/delete data |

Personalisation is derived from real inputs, not a template: body composition feeds BMR/TDEE and
macro targets (Mifflin-St Jeor, Katch-McArdle fallback), goal + experience + equipment choose the
split and prescriptions, available minutes budget the session volume.

## Module map

```
:app                      single Activity, NavHost/destination bar, theme switch, next-session widget
:core:model               pure Kotlin domain — no Android, no coroutines, fully unit-tested
:core:data                Room, DataStore, repositories, plan JSON codec, reminders, Hilt
:core:designsystem        Material 3 theme, components, charts, Media3 video player
:feature:onboarding       questionnaire → profile → generated plan
:feature:plan             dashboard, plan browser, day detail, settings
:feature:workout          session overview, player, summary
:feature:progress         trends, PRs, measurements, history
```

Dependency direction is strictly one-way: `feature:* → core:data → core:model`, `feature:* →
core:designsystem`. `:app` depends on everything and owns navigation only. `:core:data` exposes
interfaces through Hilt bindings, so feature view-models never touch Room or DataStore types.

Architecture per screen is MVVM + unidirectional data flow: `XxxRoute` (stateful, injects the
view-model) → `XxxContent` (stateless, previewable) with one immutable `XxxUiState` per
view-model and one-shot effects delivered over a `Channel`.

## Content

- **62 exercises** in `core/data/src/main/assets/exercises.json`, each with setup, 3–5 cues,
  common mistakes, breathing, tempo and equipment.
- **13 looping demo clips** (`assets/videos/<pattern>.mp4`) plus **62 thumbnails**
  (`assets/thumbnails/<exercise-id>.jpg`), all generated by `tools/generate_demo_videos.py`.
- Clips are intentionally schematic placeholders. They resolve per exercise →
  per movement pattern → icon placeholder, so real footage is a **data-only** change: drop an MP4
  in and set `videoAsset`. See `docs/CONTENT.md`.

## Quality gates

- **Unit tests:** 104 JVM tests over the domain engine (`./gradlew :core:model:test`), plus data-layer
  tests for the plan codec and shipped catalogue; Compose instrumentation smoke tests cover primary actions,
  destination selection and chart accessibility semantics (run on an emulator/device).
- **CI** (`.github/workflows/android-ci.yml`): assemble debug, run unit tests, run lint, verify the
  R8 release build; tagged builds attach the unsigned APK/AAB.
- **Lint:** `abortOnError = true`, `checkDependencies = true`, committed baseline.
- **Release:** R8 + resource shrinking with explicit keep rules for kotlinx.serialization, Room and
  Media3.
- **Privacy:** no `INTERNET` permission, no analytics SDK, backup/device-transfer excluded in
  `res/xml/data_extraction_rules.xml`, in-app data export and delete.

## Conventions

Kotlin official style · 4-space indent · no wildcard imports · versions only in
`gradle/libs.versions.toml` · conventional commits · `XxxScreen`/`XxxContent`/`XxxViewModel`
naming · immutable UI state · `sealed interface` for effects.

## Safety

The app is an educational training tool, not medical advice. It shows a disclaimer during
onboarding, enforces conservative calorie floors, blocks under-18 profiles from unsupervised
programmes, and every exercise carries safety notes where relevant. Consult a professional before
starting a new programme.
